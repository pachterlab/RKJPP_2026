## Project Purpose

This is a statistical analysis research repository investigating information-theoretic bounds on the relationship between radiology imaging phenotypes (CT/MRI) and genomic alterations (somatic mutations, CNVs, SNPs). The goal is to characterize *fundamental* predictive limits — mutual information, rate-distortion bounds, data processing inequality constraints — rather than to build a specific predictor. See README.md for the full research framing.

## Repository Layout

- `rgit/` — core Python package for the cohort pipeline (config, data loading, report). The estimator itself (`rgit/model.py`, `rgit/bounds.py`) is a re-export of the standalone `attainable-information` package at https://github.com/pachterlab/attainable_information (local checkout: `~/Desktop/attainable-information`); make estimator changes there, not here
- `notebooks/` — the companion notebook `radiogenomic_recoverability.ipynb` that produces the per-cohort figures, and `notebooks/figures/` holding every generated figure and `stats.json` that `main.tex` includes or quotes (tracked in git)
- `scripts/` — the data-processing pipeline named in the manuscript and the scripts that produce the attainable-information figures (see README.md for the run order)
- `data/` — datasets (not committed to git)
- `rgit_lean/` — Lean 4 + Mathlib proofs of the manuscript's algebraic propositions (`./check.sh` builds them)
- `main.tex` — the manuscript

## Mathematical Conventions

The manuscript (`main.tex`) uses standard information-theory notation:

- $I(X;Y)$ for mutual information
- $H(X)$ for entropy
- $R(D)$ for rate-distortion function
- Random variables in uppercase, realizations in lowercase
- Imaging features: $X$ or $\mathbf{x}$; genomic features: $G$ or $\mathbf{g}$

Keep notation consistent between the LaTeX manuscript and code (variable names in Python should mirror the math where practical).

## Code Conventions

- Statistical estimators belong in `rgit/` as importable functions, not embedded in notebooks
- Notebooks should call `rgit` functions; heavy computation stays out of notebook cells
- Scripts in `scripts/` should be runnable standalone with `python scripts/<name>.py`
- Data loading paths should be relative to the repo root or configured via environment variable, not hardcoded

## LaTeX Workflow

The manuscript is compiled from `main.tex`. Use `latexmk -pdf main.tex` to build. Figures generated by notebooks or scripts should be saved to a `notebooks/figures/` directory and included via `\includegraphics`.

## Writing style

Write with the professional academic tone of a machine learning researcher. Use American English spelling (e.g., color, behavior, tumor, characterize). Do not use italics for emphasis. Do not overuse the word "honest" unless there is a formal definition of "honesty" in the context of the method. Be prudent with em-dashes, semicolons, and colons; you can express ideas in simple sentences. Be prudent with sentence structure that involves "it is not X, but Y". Make sure not to overstate any claims unless absolutely true (e.g., we provide a tight lower bound, we provide optimal conditions). Do not use too emotionally charged or biased of language in the results section; results should be unbiased and objective. Use sections "Introduction", "Related Work", "Methods", "Experiments", "Conclusion". Use the present tense when describing the method and results, and the past tense when describing what was done in the experiments. Avoid having too many short subsections. Subsection titles should be descriptive of the content, not catchy or clever. Use the active voice when possible. Avoid passive voice unless it is more concise or clearer. Avoid using "we" or "our" unless it is necessary for clarity; prefer passive constructions or third-person descriptions of the method and results. Look at some of the accepted papers at ICLR 2026 for reference on tone and style: https://openreview.net/group?id=ICLR.cc/2026/Conference#tab-accept-oral.

## Adding References

To add a citation by DOI:
1. Fetch BibTeX from `https://doi2bib.org/bib/<DOI>` using WebFetch
2. Append the returned BibTeX entry to `ref.bib`
3. Use the entry key in `\cite{}` at the relevant location in `main.tex`
